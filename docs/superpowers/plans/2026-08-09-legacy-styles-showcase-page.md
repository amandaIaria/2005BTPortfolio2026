# Legacy Styles Showcase Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `/ui-kit/legacy-styles` route that renders the pasted legacy BT-Design-System HTML, styled by compiling `packages/design-system/legacy-bt-scss/_bt.scss` to real CSS for the first time, isolated in a Shadow DOM.

**Architecture:** A new generic `ShadowHtml` component (in `@design/system`) attaches a shadow root and injects compiled CSS + raw HTML into it. A new `legacy-styles-page.tsx` (also in `@design/system` — its first React content) feeds it the compiled legacy CSS (via Vite's `?inline` import) plus a Material Icons font import, inside a page shell matching `UiKitPage`'s header treatment. A new file-based route mounts that page under `/ui-kit/legacy-styles`.

**Tech Stack:** React 19, Vite 7 (native `.scss` support via the `sass` package + `?inline` imports), TanStack Router (file-based routing), Vitest + Testing Library + jsdom.

## Global Constraints

- No Jira ticket / Figma URL, no two-worktree-version comparison for this task — content is a verbatim legacy-HTML port with nothing to compare design-wise (explicit user choice).
- Style isolation is Shadow DOM — the legacy SCSS's global resets (`_generic/_generic.scss`, `_elements/_elements.scss`) must not leak into the rest of the SPA, and the app's own Tailwind/shadcn styles must not leak into the legacy content.
- No legacy JS behavior (textarea auto-grow, form validation) — markup and CSS only, static.
- No HTML sanitization (DOMPurify etc.) — the injected HTML is a fixed, developer-authored string compiled into the bundle, not runtime user input.
- Do not touch `UiKitPage` (`packages/general-components/src/pages/ui-kit-page.tsx`) — replicate its header shell inline in the new page instead of extracting a shared layout, to avoid touching already-shipped code for one new consumer.
- Never manually edit `src/routeTree.gen.ts` — it's regenerated by the TanStack Router Vite plugin on build/dev.
- Do not run `npm run check` (repo-wide `prettier --write`) on this branch — confirmed footgun from prior work on this same branch (reformats unrelated files repo-wide). Use `npx prettier --check <file>` (no `--write`) scoped to touched files instead.

Create `packages/design-system/src/components/shadow-html.tsx`:

```tsx
import { useEffect, useRef } from 'react';

type ShadowHtmlProps = {
  css: string;
  html: string;
  className?: string;
};

export function ShadowHtml({ css, html, className }: ShadowHtmlProps) {
  const hostRef = useRef<HTMLDivElement>(null);

  useEffect(() => {
    const host = hostRef.current;
    if (!host) return;
    const root = host.shadowRoot ?? host.attachShadow({ mode: 'open' });
    root.innerHTML = `<style>${css}</style>${html}`;
  }, [css, html]);

  return (
    <div data-component="shadow-html" ref={hostRef} className={className} />
  );
}
```

This silently resolves the whole compiled CSS to an empty string (Vite's real resolution error gets swallowed in Vitest's SSR module runner) rather than erroring loudly. Fixing this means editing `legacy-bt-scss/`, which the prior plan (`docs/superpowers/plans/2026-08-09-design-system-package.md`) established as byte-identical-to-upstream reference material. The user approved this specific deviation: fix the `normalize.css` import for real (install the package, keep the reset), and delete the `material-design-icons` import entirely (redundant — this task's page already loads Material Icons via a Google Fonts CDN `@import`, covering the same glyphs a different way). Step 1 below implements this; everything else in `legacy-bt-scss/` remains untouched.
